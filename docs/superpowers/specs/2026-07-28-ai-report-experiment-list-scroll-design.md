# AI 报告页实验列表刷新与滚动设计

## 目标

修复学生端 `src/views/student/AIReport.vue` 左侧实验列表只能看到约四条且无法继续滚动的问题。每次进入 AI 报告页都重新获取当前学生的全部实验，左侧列表在桌面端可视区域内独立纵向滚动。

## 根因

- 页面挂载时仅在 Pinia 中的 `experimentList` 为空时请求接口，可能复用其他页面留下的旧列表，无法保证进入页面时数据完整且最新。
- 左侧卡片使用固定 `80vh`，同时页面外层也负责纵向滚动；卡片、卡片正文、加载状态和列表之间的可收缩高度链不够明确，导致列表内容可能被裁切，却没有形成可靠的内部滚动区域。
- `filteredExperiments` 直接过滤并排序整个 `experimentList`，没有 `slice` 或分页限制；“四条”是可见区域问题，不是模板主动截断。

## 设计

### 数据刷新

- `AIReport.vue` 每次挂载都调用 `experimentStore.fetchExperimentList()`，不再以 store 是否为空作为请求条件。
- 保留 store 现有 loading、异常处理和空数组回退行为。
- 保留搜索、排序和实验选择逻辑，不在本次改动中增加分页。

### 左侧独立滚动

- 左侧实验卡片高度使用基于当前视口与学生端页头、内容间距、页脚的计算值，并设置合理的最小高度。
- 在页面局部样式中明确设置实验卡片为纵向 flex 容器；卡片正文使用 `flex: 1`、`min-height: 0` 和 `overflow: hidden`。
- 实验列表使用 `flex: 1`、`min-height: 0`、`overflow-y: auto`，使鼠标滚轮在左栏内浏览全部实验。
- 加载状态容器保持内容自然高度，不拦截列表容器的溢出计算。
- 移动端不强制固定桌面高度，让列表随页面自然展开，避免小屏形成嵌套滚动陷阱。

### 变更边界

- 只修改 `AIReport.vue` 及其针对性回归测试。
- 不修改公共 `UiCard`、`LoadingState`、学生端全局布局或后端接口。
- 不改变实验可见权限、状态排序、报告生成条件及右侧详情行为。

## 错误与状态处理

- 请求期间继续显示现有加载状态。
- 请求失败时沿用 store 的日志记录和空列表回退，页面显示“没有找到实验”。
- 搜索无结果时继续显示相同空态。

## 验证

- 先添加失败的源代码级回归测试，证明页面挂载必须刷新列表，模板不截断实验数组，并且桌面端左栏具备完整的独立滚动高度链。
- 实现最小修改后运行该测试，确认由失败转为通过。
- 运行项目现有相关测试、`npm run lint` 和 `npm run build`。
- 条件允许时在桌面宽度检查：实验数量超过四条时可滚动到底、搜索仍有效、点击实验仍更新右侧详情。
